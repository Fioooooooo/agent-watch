### Claude Code Projects：从资料文件夹升级为长期 Multi-Agent 协调层

- **来源**：Anthropic / Claude Code
- **标题**：Projects redesigned: from folder to conversation
- **发布时间**：2026-09-17
- **Topics**：Agent Harness、multi-agent、long-running agents、shared memory、context engineering、cloud sessions、workflow
- **Priority**：High
- **Original**：https://claude.com/blog/projects-redesigned
- **是否值得阅读全文**：是

#### What changed

Anthropic 将 Claude Projects 重设计为面向长时间、复杂任务的协调层，并首先以 beta 形式进入 Claude Code。用户在 Project 中配置目标以及 repo / context 后，Claude coordinator 会负责 scope request、delegation、parallel coordination、review 和 final assembly，而不是要求用户自己维护多个 session 之间的任务拆分和 handoff。

每个被派发的 thread 都是一条完整的 Claude Code cloud session，运行在自己的 branch 与 repo copy 中。Coordinator 可以创建新 thread，也可以把工作路由给已有 thread；thread 内部还可以继续通过 subagents、loops 和 workflows 进一步拆解任务。多个 thread 修改相同代码时并没有引入隐藏的自动合并语义，而是继续通过正常的 PR / merge conflict 机制解决代码冲突。

#### Technical details

这一版本形成了清晰的多层运行结构：

- **Project scope**：保存长期 goal、environment、connectors、plugins、instructions、model，以及跨任务共享的 memory 和 library；
- **Coordinator**：负责理解总目标、拆解、派发、跟踪、审查和汇总，不直接把所有执行塞进一个上下文；
- **Thread / Session**：每个 worker thread 是独立 Claude Code cloud session，拥有自己的 branch 和 repo copy，可以单独观察和人工 steer；
- **Subagent / Loop / Workflow**：thread 内部还可以继续使用更细粒度的执行机制；
- **Shared memory**：所有 thread 都会向同一个 Project memory 写入并从中读取信息，使项目决策、约束和工作习惯跨 session 延续；
- **Library**：用户文件与 Agent 产出的 artifacts 被保留为 Project 级材料，使后续任务能够复用此前结果；
- **Resource control**：coordinator 与 worker threads 可以分别选择 model 和 effort level，并暴露 Project-specific usage。

这意味着 Claude Code 的状态层次已经不再只有 conversation / session。Project 成为 session 之上的长期状态边界，而 thread 是可以并行、独立运行和恢复的执行单元。

#### Why it matters

长期 Coding Agent 的关键问题之一，是如何避免把所有历史、计划、代码研究和执行状态都塞进一个不断膨胀的 conversation。Claude Code Projects 给出的方案不是继续扩大单 session，而是把任务拆成多个独立 session，再通过 coordinator 和 Project-level shared memory 维持整体连续性。

这与近期 LangChain Deep Agents 的 fork / isolated context、Qwen Code Agent Board，以及 Codex 对 worker authorization / memory 的拆分形成同一条技术方向：**多 Agent 系统开始显式设计不同层级的状态边界，而不是默认所有 Agent 共享同一个上下文。** Claude Projects 的特点在于它把这种结构直接落到了跨天、跨 repo 的真实软件工程产品中。
