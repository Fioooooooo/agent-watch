### 1. Gemini CLI 0.61.0：Prompt Injection 防护、sandbox 边界与 Agent loop 状态一起加固

- **Source**：Google / Gemini CLI
- **Published**：2026-09-23
- **Topics**：Prompt Injection、Sandbox、Agent Runtime、State Integrity、Security
- **Priority**：P1
- **Original**：[Gemini CLI latest changelog](https://github.com/google-gemini/gemini-cli/blob/main/docs/changelogs/latest.md)
- **What changed**：v0.61.0 将间接 Prompt Injection 防护、sandbox 文件系统边界加固，以及 `AgentLoopContext` 属性保留纳入稳定版本。
- **Technical details**：官方 changelog 明确提到，构建文件修改与不可信 command flags 会触发间接注入防护；sandbox 增强文件系统边界并隔离内部 runtime state；`AgentLoopContext` 在对象展开过程中保留完整属性。
- **Why it matters**：这三个改动分别对应输入来源、执行边界和状态完整性。它们被放在同一发布面，说明 Agent 安全不再只是权限提示，而是与 loop state 和 sandbox runtime 一起设计。
- **Worth reading full original**：是

### 2. GitHub Copilot：本地 sandbox 与持续代码审查能力进入产品层

- **Source**：GitHub Copilot
- **Published**：2026-09-23
- **Topics**：Local Sandbox、Code Review、Agent Governance、Deployment Feedback
- **Priority**：P1
- **Original**：
  - [Local sandboxing in the GitHub Copilot app](https://github.blog/changelog/2026-09-23-local-sandboxing-in-the-github-copilot-app/)
  - [More ways to request and configure Copilot code reviews](https://github.blog/changelog/2026-09-23-more-ways-to-request-and-configure-copilot-code-reviews/)
- **What changed**：Copilot app 增加本地 sandboxing；Copilot code review 增加更细的个人配置和企业级默认设置。
- **Technical details**：local sandboxing 用于限制 Agent 对本地文件、网络资源和凭据的访问范围；code review 配置开始覆盖更多 Copilot 计划，并支持企业级默认策略。
- **Why it matters**：Harness 的安全控制从“是否允许调用某个工具”下沉到本地执行环境，同时代码审查开始具备持续配置与组织级治理属性。
- **Worth reading full original**：是

### 3. Cursor Rollouts / Security Review：Agent 从生成修改延伸到部署验证与安全回查

- **Source**：Cursor
- **Published**：2026-09-23
- **Topics**：Coding Agent、Code Review、Deployment Monitoring、Security Review、Bot Development Kit
- **Priority**：P1
- **Original**：[Cursor changelog](https://cursor.com/changelog)
- **What changed**：Cursor 发布 Rollouts 与 Security Review 两个 Bot。Rollouts 监控 Pull Request 变更部署后的健康状态；Security Review 在每个 Pull Request 上检查可利用漏洞。
- **Technical details**：Rollouts 会读取 diff 与受影响系统，生成 monitoring plan，列出风险、预期影响、需要检查的信号以及监控缺口，并在部署后按环境报告 `verified healthy`、`regression detected` 或 `inconclusive`。Security Review 面向 Pull Request 进行持续安全检查。
- **Why it matters**：Coding Agent 的执行边界从代码生成扩展到变更验证。Harness 开始连接代码上下文、部署遥测、监控计划和安全结果，形成跨阶段的持续 Agent 工作流。
- **Worth reading full original**：是

### 4. Qwen Code 0.24.4：workspace session catalog 与 managed tool state 继续显式化

- **Source**：Qwen / Qwen Code
- **Published**：2026-09-22
- **Topics**：Session Management、Workspace Catalog、Tool Runtime、Daemon、Skills
- **Priority**：P2
- **Original**：[Qwen Code releases](https://github.com/QwenLM/qwen-code/releases)
- **What changed**：v0.24.4 增加 monitor tool system-prompt guidance；相邻 nightly 增加批量 workspace session catalogs、managed tool execution state，并将 Agent tool 的 prompt-writing guidance 移入 bundled skill。
- **Technical details**：workspace session catalog 让 daemon 可以批量发现和管理工作区会话；managed tool execution state 让工具执行状态成为显式运行时数据；将 Agent tool 指导内容移入 bundled skill，降低系统提示负担。
- **Why it matters**：这组改动把 session discovery、tool lifecycle 和 prompt guidance 分成不同层次，符合 Agent Harness 逐步拆分状态、工具与指令来源的方向。
- **Worth reading full original**：持续观察
