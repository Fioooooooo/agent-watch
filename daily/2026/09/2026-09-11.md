# Agent 一手情报｜2026-09-11

## 每日摘要

今天归档 2 条高价值材料，它们共同指向一个变化：**Agent Harness 正在把“谁能说什么、从哪里接着执行、模型看到哪些工具、权限规则如何解释”从隐式行为变成明确的运行时契约。**

Codex Python SDK 0.154.0 新增 `ExternalMessage`，明确区分外部消息进入正在执行的 turn 与真正的用户授权；同时把 resume / fork 的历史返回范围、单轮服务等级和来源元数据显式化，并说明晚加入的 turn handle 只从附着点开始接收事件，不自动重放此前输出。

Claude Code 2.1.268 则继续处理同一类问题：第三方模型入口的 system prompt 与工具列表改为和一方会话保持一致，工具集合在整个会话中保持 byte-stable；resume 后的上下文顺序、prompt cache、extended thinking、MCP 工具、权限规则和 symlink 路径解析都继续收紧。

这两项更新说明长期运行、多 Agent、跨 SDK / CLI / MCP 的系统不能再只把状态定义为 transcript。消息来源的权限等级、事件从哪个位置开始可见、哪些工具属于当前上下文、恢复前后的输入是否等价、路径规则是否仍然生效，都开始成为需要显式定义和持久化的 Harness 状态。

**阅读建议：** Codex Python SDK 0.154.0 值得重点看，尤其是 `ExternalMessage` 与 turn attachment 语义；Claude Code 2.1.268 适合结合昨天的恢复正确性一起看，它正在把“上下文稳定性”和“权限正确性”继续收敛到同一个运行时问题。

## 完整材料

### 1. OpenAI Codex Python SDK 0.154.0：消息权限与会话附着点成为显式 API 语义

- **来源：** OpenAI / Codex
- **发布时间：** 2026-09-11 03:51（北京时间；官方 Release 2026-09-10 19:51 UTC）
- **主题：** Agent Runtime、SDK、Permissions、Recovery、Context Engineering
- **优先级：** ★★★★★
- **原文：** <https://github.com/openai/codex/releases/tag/python-v0.154.0>

#### 发生了什么

Codex Python SDK 0.154.0 增加了一组直接影响 Agent Harness 边界的能力：

- `ExternalMessage` 可进入同步或异步 `run()` / `turn()`，既可以启动一轮，也可以在普通 turn 正在执行时加入；
- 官方明确说明 `ExternalMessage` 具有 tool-level authority，但**不授予 user authorization**；
- 外部消息消费者拥有独立事件流，消息进入执行过程与用户授权被拆成不同概念；
- resume / fork 新增 `include_turns`，控制读取历史时是否包含 turn；
- 新增 `turn_service_tier`，可以只对新启动的一轮设置服务等级；
- 新增 `source` 元数据；
- 手工构造或晚加入的 turn handle，只从其 attachment point 开始接收事件，不会自动重放更早输出；
- 如果需要已保存历史，官方建议使用 `thread.read(include_turns=True)`。

#### 技术细节

这次最值得注意的是 `ExternalMessage` 对权限的定义。过去很多 Agent SDK 会把“有一条新消息进入当前任务”与“用户授权了新的动作”混为一体。Codex 现在明确区分：

```text
消息进入运行中 turn
        ≠
用户授权新的能力或动作
```

同时，late-joining handle 不自动重放历史，说明事件观察也具有明确的时间边界：一个消费者从什么时候附着，就从什么时候开始拥有可见事件。历史读取与实时事件流被拆开处理。

因此一个 Codex thread 的运行时状态至少开始包含：

```text
thread
├─ saved history
├─ active turn
├─ message authority
├─ user authorization
├─ attachment point
├─ independent event streams
├─ source metadata
└─ per-turn service tier
```

#### 为什么重要

对于多 Agent、外部系统回调、Human-in-the-loop、MCP 或后台任务来说，外部输入经常会在主任务运行过程中到达。如果所有输入都被当成“用户消息”，很容易把信息传递误当成授权升级。

`ExternalMessage` 的语义说明 Agent Harness 开始显式建模“消息从哪里来、能影响什么、是否改变授权边界”。这类权限分层比单纯增加一个消息接口更重要，因为它决定长期任务和多参与方系统能否安全组合。

**是否值得阅读全文：** 是。重点看 `ExternalMessage`、resume / fork 的历史选择，以及 late-joining turn handle 的事件可见性说明。

### 2. Claude Code 2.1.268：上下文稳定性与权限正确性继续合并为运行时约束

- **来源：** Anthropic / Claude Code
- **发布时间：** 2026-09-11 04:30（北京时间；官方 Release 2026-09-10 20:30 UTC）
- **主题：** Coding Agent、Context Engineering、Permissions、Recovery、MCP、Sandbox
- **优先级：** ★★★★★
- **原文：** <https://github.com/anthropics/claude-code/releases/tag/v2.1.268>
- **Changelog：** <https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md>

#### 发生了什么

Claude Code 2.1.268 的变更很多，但与 Agent Harness 最相关的部分集中在两个方向。

第一，继续保证不同入口和恢复路径下的模型上下文保持稳定：

- Bedrock、Vertex 和 Foundry 的 system prompt 改为以 attachments 传递环境、模型与设置详情，与 Anthropic 一方会话保持一致；
- 这些第三方入口的 tool list 在整个会话中保持 byte-stable，晚连接工具改为 deferred definitions，而不是重写既有 tool block；
- SDK 使用 `excludeDynamicSections` 时，不再因首条消息每次重新渲染而破坏 prompt caching 和 extended thinking；
- `/compact` 后恢复会话时，restored-file notes 顺序保持确定；
- SDK prompt suggestions、side questions 和 `/rename` 不再错误使用压缩前的 conversation；
- `--continue` / `--resume` 不再在首条消息重新读取整个 transcript。

第二，权限规则继续从表层路径匹配向真实执行语义靠拢：

- deny / ask 规则现在能正确覆盖 symlink 目录的真实路径与别名路径；
- 当 `env -C`、`eval` 等命令让静态分析无法可靠确定路径时，Read / Edit deny rule 不再被绕过；
- 本地 Cowork 在跳过所有 approvals 时，Artifact tool 仍拒绝读取 session folders 之外或 symlink 后的本地文件；
- auto mode 被拒绝时，Claude 会收到具体命中的规则，并被要求先尝试安全替代方案、继续完成不相关工作；
- policy-helper 在 headless 模式下也会输出警告。

此外，版本还修复同名 agent file 在未信任目录中影响 respawned teammate 的问题，并继续处理 MCP 密钥泄露、managed settings 与 gateway 网络边界。

#### 技术细节

这批变化把两个过去常被分开的议题连接起来：

```text
上下文正确性
├─ system prompt 是否一致
├─ tool list 是否稳定
├─ compaction / resume 后顺序是否一致
└─ reasoning / cache 是否连续

权限正确性
├─ 路径别名是否等价
├─ symlink 是否改变规则
├─ 静态分析失败时是否保守处理
└─ 不同执行入口是否应用同一策略
```

两者的共同要求是：**同一个逻辑会话和同一条策略，在不同 provider、resume 路径、工具加载时机和文件路径表达下，都应保持等价。**

#### 为什么重要

Agent 运行时间越长，执行路径越多，越容易出现“逻辑上还是同一个任务，但恢复后模型看到的上下文已经变了”或者“逻辑上还是同一个文件，但因为 symlink / shell 解析方式变化，权限规则没有命中”的问题。

Claude Code 2.1.268 继续把这些问题从局部 bug 提升为 Harness 的一致性要求：模型上下文、工具集合和权限策略都需要在不同运行路径下保持语义稳定。

**是否值得阅读全文：** 是。重点关注 byte-stable tool list、resume / compaction、symlink permission、第三方 provider 上下文一致性几组变更。
