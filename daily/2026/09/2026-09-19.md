#### What changed

GitHub 9 月 18 日的 Copilot 周更明确加入两项 Harness 层能力：code review 可以使用 shell tools 对修改进行验证；Lite reviews 会组合多个 Agent 的 findings。与此同时，新的 review experience 会在后续 commit 和重新 review 之间持续维护发现状态，将问题区分为 Open、Resolved since last review 和 Previously missed，并根据代码变化自动判断此前评论是否已经解决。

#### Technical details

这使 Copilot code review 同时具备三类此前通常分散的 Agent 能力：

- **Tool-backed validation**：审查不再只依赖静态 diff/context，Agent 可以执行 shell 工具验证修改；
- **Multi-Agent aggregation**：Lite review 会组合多个 Agent 的发现，最终向用户呈现统一结果；
- **Persistent review state**：findings 跨后续 commit 和重复 review 保留状态，Agent 会重新验证问题是否已经解决，并保留此前遗漏但后来发现的问题。

因此 Review 的状态单位开始从“单次模型请求”提升为整个 PR 的审查生命周期。PR 本身成为 Harness 的持久任务对象，而 commit 是推动审查状态机变化的事件。

#### Why it matters

这与本周其他 Coding Agent 的变化存在直接联系。Claude Code Projects 把长期状态提升到 Project scope，VS Code Agent Host 把 Session 从前端和 execution environment 中解耦，而 GitHub Copilot 正在把持续状态放到 PR / Review scope。三者共同说明 Agent 系统不再试图把所有状态放进 conversation，而是围绕真实软件工程对象建立不同生命周期的状态边界。

对于 Harness 设计，这意味着未来需要同时管理 Project memory、Session runtime state、workspace / branch state，以及 PR / review findings 等外部持久状态，并决定每次 Agent 执行时如何重新装配这些状态。
