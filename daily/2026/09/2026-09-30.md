## 完整材料

### 1. Qwen Code v0.24.7：Managed Agent / Hosted Harness 进入系统化运行时阶段

- **Source**：Qwen / Qwen Code
- **Title**：Release v0.24.7
- **发布时间**：2026-09-29
- **Topics**：Managed Agent、Hosted Harness、Workspace Runtime、ACP、Recovery、Durable Session、Memory、Computer Use
- **Priority**：P1
- **Original**：[Qwen Code v0.24.7 Release](https://github.com/QwenLM/qwen-code/releases/tag/v0.24.7)
- **What changed**：官方 Release 同时加入 workspace-bound sessions、Managed Runtime 工具执行、ACP legacy / managed engine 路由、Hosted Harness 的 no-tool 与 file-tool turns、Managed tool result contract、workspace runtime identity、event replay、durable session operations、workspace holder recovery、structured memory recall、remote desktop relay、durable workspace collaboration state 等能力。
- **Technical details**：
  - 运行时开始区分普通引擎、Managed Engine、Hosted Harness 和 Workspace Runtime，并通过 ACP bridge 在不同执行引擎之间路由会话。
  - Session 不再只是本地对话记录，而是具备查询、事件回放、关闭、归档、删除、恢复和 durable log 等生命周期能力。
  - Workspace 成为执行边界和路由实体，Managed Runtime 工具在指定 workspace 目录运行，工作区变更可同步到配对引擎。
  - Hosted execution 增加 tool-turn、foreground shell、file-tool、no-tool 等受控阶段，并通过 fault gates、reply-loss、process-crash、cancellation、SSE gap 等测试验证恢复语义。
  - 内存系统新增 structured scan、bounded retrieval、on-demand recall；工具结果增加本地 segment store，减少长会话中对完整历史的重复重放。
  - 同一版本还加入 Landlock fallback、远程桌面 relay、worktree branch session 和 lazy-loaded tools，扩展了 sandbox、Computer Use 与任务隔离的运行时面。
- **Why it matters**：Qwen Code 正把 Coding Agent 从单进程 CLI 推向可托管的 Agent runtime。关键变化不在于功能数量，而在于执行、会话、工作区、工具结果、内存和恢复都开始拥有独立的持久化合同与故障语义。
- **是否值得阅读全文**：是
