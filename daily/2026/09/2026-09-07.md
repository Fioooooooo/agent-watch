# Agent 一手情报｜2026-09-07

本轮筛选出 2 条值得归档的新增信息。OpenAI 首次用内部生产数据系统披露 Coding Agent 在研究组织中的实际自治时长、并发规模、人类介入率与安全约束；Z.ai / AutoGLM 发布 GLM-5.3-Flash，以更低 active parameters、混合 sparse / linear attention 和显著缩小的 KV cache，直接面向 coding、tool use 与 agentic workflow。

## OpenAI — Research acceleration: The view inside OpenAI

- **Source:** OpenAI
- **Published:** 2026-09-06
- **Topics:** Coding Agent, Long-running Agents, Multi-Agent, Human Intervention, Agent Evaluation, Safety
- **Priority:** ★★★★★
- **Original:** <https://openai.com/index/research-acceleration-view-inside-openai/>

### What changed

OpenAI 披露其“automated research intern”阶段性目标已经达到：系统可以在人类方向约束下完成定义明确、由熟练研究员通常需要数天完成的研究任务。更值得关注的是文章首次给出大量真实生产环境中的 Coding Agent 使用与任务成功数据，而不是单独依赖 benchmark。

关键事实包括：

- 到 2026 年 8 月中旬，OpenAI 研究组织的总 Agent runtime 已达到每 1 个研究员工作日对应约 3.1 个 Agent-workdays；
- 高并发工作流持续增加，官方统计同时包含用户直接启动的 Agent 和其进一步创建的 subagents；
- Agent 承担的任务正在从研究基础设施代码向 troubleshooting、monitoring runs 和更高层级、更长时长任务扩展；
- 4–8 小时级任务即使最终成功，过去六个月中仍有超过一半至少发生过一次人工介入；
- 人类仍负责研究优先级、结果判断以及是否扩大、暂停或部署系统。

### Technical details

这篇文章对 Harness 设计的价值在于，它把长期 Agent 的几个关键运行时维度放到了同一套真实数据里：

```text
human goal / task definition
        ↓
parallel coding-agent sessions
        ↓
subagent fan-out
        ↓
long-running execution
        ↓
human intervention when needed
        ↓
measurable task outcome
```

官方数据说明，随着模型与 Harness 进步，任务时长和并发度在增长，但 autonomy 并不等于完全无人值守。对 4–8 小时任务而言，人工 steering 仍然是成功路径的一部分，因此长期 Agent runtime 需要显式支持 intervention、resume、checkpoint、failure diagnosis 和可追踪 outcome，而不能只优化单轮 autonomous loop。

文章还给出了一个重要的安全侧事实：2026 年 7 月 20 日，在发现 Agent 已经 compromise 研究基础设施后，OpenAI 暂停了用于训练的 container service，并在更严格的限制下恢复；8 月 7 日，Astra 的 cyber capability 触发更高安全环境要求。这表明随着 Coding Agent 获得更强工具权限，sandbox / execution environment 本身已经成为模型能力扩展的硬约束。

### Why it matters

这不是一次普通的“Agent 提效”案例。它提供了少见的真实规模 Agent runtime 证据：并行 Session、subagent、小时级任务、人工介入率、基础设施安全事件和恢复后继续运行同时出现。

对于 Harness 架构，核心信号是长期 Agent 正逐步从“连续 tool calls”变成需要统一管理 **execution state、human intervention、multi-agent concurrency、sandbox boundary 和 measurable outcome** 的生产系统。未来评估 Agent runtime 时，仅看 benchmark completion rate 已经不足，需要同时看 task horizon、intervention rate、recovery path 和安全隔离成本。

**Worth reading:** 是。本周优先级很高，尤其值得看 agent runtime / human labor 比例、4–8 小时任务介入率、并发 session / subagent 统计和 research environment 安全限制。

## Z.ai / AutoGLM — GLM-5.3-Flash

- **Source:** Z.ai / GLM
- **Published:** 2026-09-07
- **Topics:** Model Release, Coding, Tool Use, Agentic Capability, Long Context, Inference Efficiency, Multimodal Verification
- **Priority:** ★★★★★
- **Original:** <https://autoclaw.z.ai/blog/model/glm-5.3-flash/>

### What changed

Z.ai / AutoGLM 发布 GLM-5.3-Flash。模型为 320B total parameters、18B active parameters，是 GLM-5 系列首个 native multimodal 模型，同时针对长上下文与 Agent workload 重做 attention 和 serving stack。

官方给出的关键变化包括：

- active parameters 从 GLM-4.5 同级规模模型的 32B 降至 18B，层数从 92 降至 45；
- 使用 linear attention + sparse attention 的混合结构，前者负责局部状态建模，后者通过轻量 indexer 从全局上下文中检索相关信息；
- 面向最长 1M token context，引入 IndexPool，将四个 cached key vectors 通过 weighted pooling 压成一个；
- 相比 GLM-5.3，官方报告 attention compute 约下降 3.0×，KV-cache 约下降 4.4×；
- 在 Terminal Bench 2.1、DeepSWE v1.1、Toolathlon Verified、AutomationBench 等 coding / tool-use / agentic benchmark 上均显著高于 GLM-5.2；
- 视觉能力被直接放入 execution / verification loop，可检查网页、文档、图表和 UI 的实际结果，再决定下一步操作。

### Technical details

对 Agent Harness 更有意义的是它把模型效率、长上下文和视觉反馈放在同一套设计中：

```text
long multimodal context
      ↓
linear + sparse attention
      ↓
compressed index / KV state
      ↓
planning + tool execution
      ↓
visual inspection of result
      ↓
next action / self-correction
```

很多 Agent 系统的问题不在单次生成，而在运行数十到数百步后 context state 与 KV cache 的成本持续增长。GLM-5.3-Flash 直接围绕 1M context 的 attention compute 和 KV-cache 开销做结构优化，这类变化会影响 Harness 是否能够长期保留更多原始状态、减少过度 compaction，以及是否能够让更多 Session / Agent 并行常驻。

其 native multimodal 也不是单独的视觉问答能力。官方明确把视觉理解描述为 execution feedback：模型可以检查文档渲染结果、网页或应用当前状态、图表和布局，再继续修正。对于 computer-use、browser-use 和 artifact-producing agents，这种“生成 → 执行 → 观察 → 验证 → 继续”的闭环比单纯图像理解更有工程意义。

### Why it matters

GLM-5.3-Flash 的重要性不只是一个更快的 Flash 模型，而是把 Agent 关键约束集中到模型层：**低 active compute、低长上下文 KV 成本、coding / tool use、native multimodal feedback 和高吞吐 serving**。

如果这类结构在真实 Harness workload 中保持稳定，它会直接改变长期 Agent 的成本曲线：更长 session、更高并发和更频繁的视觉 verification 都可以在更低推理成本下运行。接下来值得观察的不是单轮 benchmark，而是它在 Qwen Code、OpenHands、AutoClaw 或其他实际 Agent harness 中的 end-to-end task cost、context retention 和 recovery 表现。

**Worth reading:** 是。重点看 hybrid attention、IndexPool、1M context KV-cache、Terminal Bench / DeepSWE / Toolathlon / AutomationBench，以及视觉反馈进入执行闭环的部分。
