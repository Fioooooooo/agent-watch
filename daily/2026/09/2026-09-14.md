## 每日摘要

今天真正值得关注的是同一个方向的两组变化：**多 Agent 协作状态和上下文成本正在从 Prompt 约定继续下沉为 Harness 的显式运行时资源。**

Qwen Code 在 9 月 13 日发布的 `v0.23.3-nightly.20260913.faa395885e` 中加入实验性的 **Agent Board**。它不是新的调度器，而是一个低层协作面：多个独立启动的 Agent 可以通过本机持久化 board 共享任务、claim / done 状态和带 TTL 的 ask / answer；写入动作带 actor 标签，记录不会自动执行，也不会自动唤醒其他 Agent。这类设计把“Agent 之间如何留下可查询、可竞争、可结算的工作状态”从聊天消息中拆了出来。

同一 nightly 还集中加入了 **上下文与 Computer Use 的预算控制**：Web Shell 提供更明确的上下文用量与手动 `/compress` 控制，并把压缩操作绑定到当前会话的 live owner；Computer Use 新增 app-bound actions、压缩原生 observation、限制 observation 大小并减少模型往返；shell 输出预算也改由实际 producer 的预算决定。它们共同指向一个工程问题：长期 Agent 的成本控制不能只依赖模型自己“少看一点”，而需要 Harness 明确管理哪些状态可见、多少内容进入上下文、谁拥有变更权限。

这批能力目前属于 nightly 预发布，**值得持续观察，但不应按稳定版本能力理解**。如果只读一份原文，优先看 Agent Board 的设计文档；上下文压缩和 Computer Use 优化可以等待进入稳定版本后再确认最终语义。

## 完整材料

### 1. Qwen Code：Agent Board 为独立 Agent 增加共享工作状态

- **Source:** Qwen Code
- **Title:** `v0.23.3-nightly.20260913.faa395885e` — Agent Board
- **Published:** 2026-09-13 22:01 UTC
- **Topics:** Multi-Agent, Agent Runtime, Coordination, Coding Agent
- **Priority:** ★★★★★
- **Original:** https://github.com/QwenLM/qwen-code/releases/tag/v0.23.3-nightly.20260913.faa395885e
- **Design:** https://github.com/QwenLM/qwen-code/blob/v0.23.3-nightly.20260913.faa395885e/docs/users/features/agent-board.md
- **是否值得阅读全文:** 是，尤其值得看 Agent Board 的边界定义。

#### What changed

nightly 新增 `agent board`：允许多个**独立启动**的 Agent 通过同一台机器上的持久化文件共享工作状态。官方明确把它定义为低层 interoperability surface，而不是 Qwen Agent Team scheduler，也不是 cross-session messaging transport。

Agent 可以创建任务、claim、完成并留下 note，也可以向指定 actor 发起带 TTL 的 ask，接收 answer / decline。board 记录保存在 `~/.qwen/boards/`，写操作需要声明 `--as` actor，但 actor 只是记录标签，不是身份认证。

#### Technical details

- board 显式保存 task owner、claim / done 与问答状态，而不是只存在于模型上下文；
- ask 区分 answer、decline、TTL expiry 和本地 wait timeout；
- settled record 不会自动删除，需要显式 prune；
- board text 被视为不可信数据，不会自动执行；
- board 不负责启动、加入、监控、唤醒或向 Agent 进程推送输入；
- 第一版明确不包含远程 board、心跳、成员列表、tmux/fleet orchestration，也不支持多个 Agent 同时修改同一 checkout。

#### Why it matters

它提供了一种介于“消息通信”和“完整工作流引擎”之间的协作原语。对多 Agent Coding 系统而言，任务所有权、结算状态、异步问答和过期语义开始成为模型上下文之外的可查询状态。这个方向与此前 session registry、peer messaging、workflow journal 的演进一致，但 Agent Board 特意保持无调度语义，使其他 Agent（包括非 Qwen Agent）也可以参与。

### 2. Qwen Code：上下文压缩与 Computer Use 开始显式受运行时预算约束

- **Source:** Qwen Code
- **Title:** `v0.23.3-nightly.20260913.faa395885e` — context / Computer Use runtime controls
- **Published:** 2026-09-13 22:01 UTC
- **Topics:** Context Engineering, Computer Use, Tool Runtime, Long-running Agent
- **Priority:** ★★★★☆
- **Original:** https://github.com/QwenLM/qwen-code/releases/tag/v0.23.3-nightly.20260913.faa395885e
- **Context design:** https://github.com/QwenLM/qwen-code/blob/v0.23.3-nightly.20260913.faa395885e/docs/design/2026-09-12-web-shell-context-compaction.md
- **是否值得阅读全文:** 观察即可；等稳定版本确认最终接口与语义。

#### What changed

同一 nightly 同时加入或调整：Web Shell 的上下文概览与手动压缩、Computer Use 的 app-bound actions 与紧凑 observation、observation 边界与模型往返优化，以及 shell 输出预算管理。

#### Technical details

Web Shell 的上下文面板开始区分 used / remaining / buffer，并暴露已有 `/compress` 能力。更重要的是，压缩不是一个无状态按钮：操作必须通过 owning live session 的 prompt lifecycle 执行，并重新检查 session/workspace ownership、busy/write-block 状态；跨 session 或 pane 切换后不能把旧结果写到新的 owner 上。历史 snapshot 不会因为 refresh 或 compression 被重写。

Computer Use 侧的 release notes 同时列出：

- `add app-bound actions and compact native observations`；
- `bound observations and reduce model round trips`；
- 针对 OSWorld 的 tool failure / efficiency 修复；
- shell output size 改为由 producer 自身预算决定。

#### Why it matters

这些变化把 Context Engineering 从“对话太长时做一次摘要”推进到运行时资源治理：上下文有可观测预算，压缩有 ownership，工具 observation 有上限，Computer Use 的模型往返成为需要主动优化的成本。对于长期 Coding Agent 与 GUI Agent，这些机制直接影响上下文污染、token 成本、恢复一致性和工具延迟。
