### Claude Code 2.1.273：网关获得 Agent 执行阶段提示，会话 fork 与权限一致性继续增强

- **来源**：Anthropic / Claude Code
- **标题**：Claude Code v2.1.273
- **发布时间**：2026-09-15 20:23 UTC（北京时间 2026-09-16 04:23）
- **Topics**：Harness、observability、session fork、permissions、MCP、multi-agent、recovery
- **Priority**：High
- **Original**：https://github.com/anthropics/claude-code/releases/tag/v2.1.273
- **是否值得阅读全文**：是

#### What changed

Claude Code 新增一组可选的 LLM gateway hint headers：`x-claude-code-request-class`、`x-claude-code-agent-type`、`x-claude-code-prev-tool-durations`、`x-claude-code-compaction`、`x-claude-code-context-compacted`，通过 `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` 开启。Remote Control 启动的会话现在可以从 Claude app fork，fork 后在用户电脑上作为后台会话继续运行。

同一版本还修复了多项 Harness 边界问题：无法完全分析的 Bash 命令在 `permissions.blockReadsOutsideWorkingDirectories` 下可能跳过授权提示；subshell 可隐藏危险 `rm`；组织关闭 Skills 后已同步的 Skill 仍保持可用；MDM / managed-settings 中的 MCP 与 connector 管理策略在 server-managed settings 同时存在时可能被忽略；MCP 自动重连最终失败后现在会明确通知；sub-agent / background agent 在最终流式回复缺少 token usage 或 model id 时不再被错误判定失败并丢失结果；SDK / stream-json 在 subagent 中途转后台后不再丢弃剩余消息与最终报告。

#### Technical details

这组 gateway headers 的价值不在 HTTP header 本身，而在于 Harness 开始向基础设施层暴露执行语义。网关此前主要看到模型、token 和请求时间；现在可以进一步知道请求属于什么 Agent 类型、是否处于 compaction 后上下文、此前工具调用耗时等。这为按 Agent 角色路由模型、识别 compaction 后质量变化、分析 tool-heavy turn 延迟以及做更细的成本治理提供了结构化信号。

Remote Control session fork 则把会话从单一前端绑定中进一步拆出：远程控制中的执行上下文可以派生为本机后台 session。结合最近多个版本持续修复 resume、background agent、MCP reconnect 和 prompt-cache continuity，可以看到 session identity 与 execution location 正在成为独立的 Harness 状态维度。

权限侧仍然遵循近期主线：静态命令分析不完整时不能默认放行，managed policy 也必须在多种配置来源叠加时保持优先级和约束语义。这个版本同时处理 Bash、Skills、MCP 和 connectors，说明权限治理已经跨越单一 tool permission，进入完整能力面的 policy consistency。

#### Why it matters

对于企业级 Coding Agent，真正需要观测的不只是模型 API 指标，而是 Agent 正处于哪个执行阶段、哪个角色、上下文是否被压缩、工具调用是否成为瓶颈，以及策略在会话迁移和后台执行后是否仍然成立。Claude Code 2.1.273 开始把其中一部分状态正式暴露给网关，同时继续修复会话分叉、后台 Agent 与 managed policy 的一致性问题，这比普通 CLI 功能更新更接近 Harness 基础设施演进。
