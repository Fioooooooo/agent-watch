# Agent 一手情报｜2026-09-15

## 每日摘要

今天收录 3 条高价值更新。最值得关注的是，长期 Coding Agent 的运行状态正在继续从“会话文本”扩展为可持久化、可恢复的完整运行契约。

Claude Code 2.1.271 开始让 WebFetch 的网络授权携带到具体命令级别，并在 streaming 输入中加入 drain marker，使权限和输入生命周期进一步从隐式行为变成显式协议；Qwen Code 0.23.4 的稳定版则集中补齐中断会话继续执行、checkpoint 诊断、hook 会话元数据、reasoning replay 与信任状态桥接。这两者指向同一个方向：resume 不再只是重新载入 transcript，而需要恢复工具、权限、hook、推理历史和运行状态的一致性。

Kimi Code 0.43.0 则值得单独观察：Goal Mode 的时间预算不再把关闭会话期间计入执行时间，并取消 24 小时上限。这是一个很小但很明确的长期任务语义变化——任务预算开始按 Agent 实际运行生命周期计算，而不是按墙钟时间粗略计费。

如果只读一项，优先看 Claude Code 2.1.271；Qwen Code 0.23.4 更适合作为近期 Harness 状态治理变化的稳定版汇总，Kimi 0.43.0 则持续观察其 Goal Mode 是否继续补齐 checkpoint、恢复和失败传播语义。

## 完整材料

### 1. Claude Code 2.1.271：网络授权进入命令级生命周期，streaming 输入增加显式 drain

- **来源**：Anthropic / Claude Code
- **发布时间**：2026-09-14 22:12 UTC
- **Topics**：permissions, network policy, session runtime, streaming
- **Priority**：★★★★★
- **Original**：https://github.com/anthropics/claude-code/releases/tag/v2.1.271
- **是否值得阅读全文**：是

**What changed**

Claude Code 2.1.271 的高价值变化不是 UI，而是两个运行时边界：WebFetch 相关的 `allowed_domains` 开始以 per-command 方式传递；streaming input 新增 `drain` marker，用于明确输入流的消费边界。版本同时继续修复 resume / compaction / background agent 等长期会话稳定性问题。

**Technical details**

命令级 `allowed_domains` 意味着网络权限可以绑定到一次具体执行，而不是只依赖全局网络配置或模型自己判断；这使权限状态更容易随 tool invocation 被记录、审计和恢复。`drain` marker 则把 streaming input “什么时候已经消费完成”从时序猜测转成显式协议状态，对中断、恢复和异步输入尤其重要。

**Why it matters**

Claude Code 最近多个版本一直在修复恢复后的 system prompt、工具集合、MCP、thinking、工作目录和权限一致性。2.1.271 延续的是同一条工程路线：长期 Agent 的正确性依赖 Harness 保存并恢复完整运行状态，而不是只保存聊天历史。

### 2. Qwen Code 0.23.4：稳定版继续补齐会话恢复与 Harness 状态治理

- **来源**：Qwen / Qwen Code
- **发布时间**：2026-09-14 17:19 UTC
- **Topics**：session recovery, checkpoint, hooks, context, permissions
- **Priority**：★★★★☆
- **Original**：https://github.com/QwenLM/qwen-code/releases/tag/v0.23.4
- **是否值得阅读全文**：是，适合结合 0.23.x nightly 变化一起看

**What changed**

0.23.4 稳定版把近期 nightly 中多项 Harness 变化汇入正式版本，包括中断会话继续执行、checkpoint 诊断、HookSessionMeta、会话信任状态桥接、reasoning replay 与历史处理等。

**Technical details**

这些变化分别落在不同子系统，但都服务于同一个目标：让一个会话在中断、压缩、hook 执行、权限变化或重新附着后仍能恢复到语义一致的运行状态。尤其是把会话元数据显式传给 hook、保存信任状态，以及对 reasoning replay 做专门处理，说明 Qwen Code 正在把过去隐含在 transcript 和进程内存里的状态拆成独立运行时数据。

**Why it matters**

这与 Claude Code 最近连续处理 resume 一致性的方向高度重合。Coding Agent 的恢复能力正在从“能重新打开会话”升级为“恢复后仍拥有正确的上下文、权限、工具与生命周期状态”。

### 3. Kimi Code 0.43.0：Goal Mode 的预算开始遵循实际运行生命周期

- **来源**：Kimi / Kimi Code
- **发布时间**：2026-09-14
- **Topics**：long-running agents, goal mode, runtime budget, context
- **Priority**：★★★★☆
- **Original**：https://www.kimi.com/code/docs/en/kimi-code/whats-new.html
- **是否值得阅读全文**：无需全文阅读，关注 Goal Mode 变化即可

**What changed**

Kimi Code 0.43.0 调整 Goal Mode 的时间预算：会话关闭期间不再消耗时间预算，并取消此前 24 小时上限。另外新增 `KIMI_CODE_PERMISSION_MODE_REMINDER`，允许停止把自动权限模式提醒持续注入模型上下文。

**Technical details**

前者把长期目标的预算从简单墙钟时间改成更接近实际执行生命周期的语义，使暂停、离线和恢复后的任务不会因为 Agent 没有运行而耗尽预算。后者则把一类重复的权限提示从模型上下文中变成可配置行为，减少不必要的上下文占用。

**Why it matters**

Goal Mode 已经不只是“持续循环直到完成”的 prompt 技巧，而开始拥有独立的预算与生命周期规则。后续值得观察 Kimi 是否继续加入 checkpoint、失败恢复、人工介入和预算跨会话继承等机制。
