## 完整材料

### Visual Studio Code 1.138：Agent Host 开始承担跨应用 Session 与执行环境宿主层

- **来源**：Visual Studio Code / Agent Host（开放发现）
- **标题**：Visual Studio Code 1.138
- **发布时间**：2026-09-16
- **Topics**：Agent Harness、session management、AHP、Codex、Dev Container、MCP、sandbox
- **Priority**：High
- **Original**：https://code.visualstudio.com/updates/v1_138
- **是否值得阅读全文**：是

#### What changed

VS Code 1.138 明确说明 Agent Host 会把 agent harness 运行在一个基于 Agent Host Protocol（AHP）的独立进程中，因此同一个 session 可以从多个 VS Code 窗口连接。本次同时扩展 Codex harness：用户可以在 GitHub Copilot subscription 与 ChatGPT subscription 之间切换模型而不丢失当前 conversation；同一个 Codex session 可以在 ChatGPT app 与 VS Code 之间继续；Codex 可以复用 ChatGPT app 的 Computer Use 配置，并调用 VS Code 内建、extension 与 MCP tools。

Workspace-less Codex quick chat 也可以直接 attach 本地目录或创建隔离 worktree，转换后保留 session title、conversation history、当前 request、selected model、permission mode 与原生 Codex thread。另一个重要变化是 Agent session 可以运行在项目自己的 Dev Container 中，使用项目定义的工具链与依赖，而不是直接使用宿主机环境。

#### Technical details

这一版本把此前常被绑定在单个 IDE / CLI 进程中的几个维度拆开：

- **Session identity**：Codex native thread 不因从 ChatGPT app 切换到 VS Code 或 attach workspace 而重新创建；
- **Frontend**：同一 session 可以跨窗口、跨应用继续；
- **Model / account provider**：同一 conversation 可以在 Copilot-backed 与 ChatGPT-backed 模型之间切换；
- **Tool surface**：Codex 进入 VS Code 后可以获得 VS Code built-in、extension 与 MCP tools；
- **Execution environment**：Agent Host 可以把 session 放进项目 Dev Container，使 Agent 使用项目工具链和依赖；
- **Workspace binding**：无 workspace session 可以在保持原 thread 与 permission mode 的情况下转为项目 session。

这种拆分使 Agent Host 更接近真正的 Harness runtime，而不是聊天 UI。AHP 负责把 harness 与宿主解耦，session 则成为可以被宿主层重新绑定到不同 frontend、workspace、tool surface 和 execution environment 的实体。

#### Why it matters

长期 Coding Agent 的一个核心问题是任务状态不能继续依赖单一客户端进程。VS Code 1.138 展示了一种更完整的宿主架构：会话身份独立于 UI，执行环境独立于会话，工具面可以由宿主动态提供，workspace 可以后绑定，模型订阅来源也可以切换。

这与 Claude Code 最近连续强化 resume、fork、background session 和权限连续性的变化属于同一方向，但 VS Code 进一步把“多种 Agent harness 的统一宿主”做成 IDE 基础设施。对于 ACP / AHP / Harness adapter 一类架构，这个实现值得持续跟踪。
