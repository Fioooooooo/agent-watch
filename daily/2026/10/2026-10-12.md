### 1. Qwen Code 0.25.1：AgentDefinition 版本固定

**Source**：Qwen / Qwen Code  
**Title**：Release v0.25.1 / execute pinned AgentDefinition revisions (#13530)  
**发布时间**：2026-10-11  
**Topics**：Agent Harness、Configuration Provenance、Session Lifecycle、Permissions、Recovery  
**Priority**：P1  
**Original**：https://github.com/QwenLM/qwen-code/releases/tag/v0.25.1  
**Implementation**：https://github.com/QwenLM/qwen-code/pull/13530

**What changed**

Managed Session 在创建时确定 AgentDefinition ID、revision 与 digest，运行时按固定定义加载模型、工具、权限模式和指令，不再动态解析最新配置。

**Technical details**

如果创建请求没有指定 revision，系统仅在接纳阶段解析一次最新版本，并固定结果；重放相同请求时保留原始 revision 和 digest。新的 AgentDefinition 只影响新会话，已有会话继续按原定义执行。常驻执行和冷启动恢复都需验证定义身份，不支持的字段明确拒绝，不会静默忽略。Agent 指令存储为通过 digest 寻址的 UTF-8 Session Store 资源，大小上限 64 KiB，并纳入事务及恢复资源集合。模型凭据不可用时在推理前返回 model_unavailable，托管环境不支持定义要求的能力则拒绝接纳或执行。

这一机制只保证 Agent 配置与会话执行的对应关系，不保证外部工具副作用自动可重放。Hosted Harness、后台 Shell、持久化工具结果等大多已在预览版收录，本次不重复算作新增。

**Why it matters**

长任务恢复必须恢复的不仅是消息，还有创建任务时生效的模型、指令、工具与权限定义。固定 revision 和 digest 能避免运行途中配置漂移，提供可追溯的执行依据。

**是否值得阅读全文**：是；重点看版本固定、重复创建、冷启动恢复和能力不匹配的失败处理。

### 2. Qwen Code 10 月 11 日 nightly：团队邮箱和 EventTransport

**Source**：Qwen / Qwen Code  
**Title**：v0.25.1-nightly.20261011.01d3e6d81a  
**发布时间**：2026-10-11 22:01 UTC  
**Topics**：Multi-agent、Session Messaging、Durable Delivery、Agent Identity、Recovery、Event Transport  
**Priority**：P1  
**Original**：https://github.com/QwenLM/qwen-code/releases/tag/v0.25.1-nightly.20261011.01d3e6d81a  
**Implementation**：https://github.com/QwenLM/qwen-code/pull/13892 、https://github.com/QwenLM/qwen-code/pull/13909

**What changed**

团队负责人使用 send_message 按成员名称或任务编号发送消息，或向全体成员广播；已完成一次运行的成员能够沿原执行链继续工作。EventTransport 为跨节点事件传输预留适配接口，但尚无实际适配器。

**Technical details**

send_message 的 to 和 task_id 必须恰好指定一个，to 为成员名称或 * 广播。广播对每名成员生成独立投递或续跑记录，并保留独立标识；当前 Turn 取消时停止继续投递。成员身份由连续执行链表示，当前状态以最新执行节点为准，完成一次任务后仍可继续接收消息。每次执行附有固定团队身份前言，结果带来源记录。

投递状态区分消息已送达、执行尚未启动、实际没有投递、启动前取消及拒绝，便于负责人决定等待、重试还是重新委派。官方报告基于 Linux、MySQL、持久化 worker 与脚本模型的 57/57 项验收，不等于真实模型在所有场景中都可靠遵循团队规则。成员之间直接通信、计划审批及团队关闭仍待实现。

事务提交后，组合发布器先通知进程内 SessionEventHub，再调用配置的 EventTransport；单个外部适配器失败记录错误，不应中断其他适配器及本地 SSE 发布。当前无消息代理、跨节点生产消费或新的部署配置，真正跨节点能力仍是后续工作。

其他运行时修复包括上下文压缩阈值、Hosted 流关闭与取消、Hook 会话、强制审批 Shell 入口和工作树状态结算，不单独计数。

**Why it matters**

持续协作需要稳定成员身份、消息投递记录、任务所有权与可恢复执行链。EventTransport 体现先明确事务与失败隔离边界，再引入分布式传输的设计；不能把扩展接口当作完整交付。

**是否值得阅读全文**：是；优先关注成员身份、投递状态、恢复规则。
