## 每日摘要

### 1. Dynamic workflows in Copilot CLI and the Copilot app

- **Source**：GitHub Copilot
- **Title**：Dynamic workflows in Copilot CLI and the Copilot app
- **发布时间**：2026-10-01
- **Topics**：Workflow Orchestration、Multi-agent、Checkpoint、Observability、Copilot SDK
- **Priority**：P1
- **Original**：https://github.blog/changelog/2026-10-01-dynamic-workflows-in-copilot-cli-and-the-copilot-app/
- **What changed**：Dynamic Workflows 在 Copilot CLI、GitHub Copilot app 和 Copilot SDK 中可用。用户可以用代码定义工作流，将自动化步骤与一个或多个 Agent 组合起来。
- **Technical details**：
  - 工作流可串行、并行或混合执行多个步骤；
  - 可以运行命令、调用工具和外部服务；
  - 可以把目标拆成并行子任务，并传递结构化结果；
  - 可以让子 Agent 互相验证；
  - 可以在 checkpoint 暂停，等待用户审核后恢复；
  - 适用于发布检查、批量 Pull Request 审查、大型代码库扫描、研究到实现的分阶段任务，以及可暂停的长时运行任务。
- **Why it matters**：工作流控制从提示词层下沉到代码层，开始具备可复用、可测试、可观察和可恢复的执行语义。它与传统的“让模型自行决定下一步”不同，更接近显式 Harness。
- **是否值得阅读全文**：是

### 2. HydraFusion：面向 Coding Agent 的多模型工作流选择

- **Source**：GitHub Copilot
- **Title**：HydraFusion in VS Code and the GitHub Copilot app
- **发布时间**：2026-09-30
- **Topics**：Multi-model Orchestration、Routing、Critique、Quality Gate、Long-running Task
- **Priority**：P1
- **Original**：https://github.blog/changelog/2026-09-30-hydrafusion-in-vs-code-and-the-github-copilot-app/
- **What changed**：HydraFusion 研究预览扩展到 VS Code 和 Copilot app。它不是单一模型，而是根据 reasoning、code generation、debugging 和 tool use 能力信号选择执行工作流。
- **Technical details**：
  - Single：单模型直接解决；
  - Cascade：高效模型先生成，质量门决定是否升级到更强模型；
  - Critique：一个模型生成，另一个模型族的只读 Critic 审查，再由生成模型修订一次；
  - 增加过程透明度和实时进度，改善长任务状态反馈；
  - 与普通 Auto 模式的差异在于，HydraFusion 同时选择工作流并在一次任务中协调多个模型。
- **Why it matters**：模型路由不再只是在请求前选一个模型，而是变成了包含升级、质量门和交叉审查的运行时策略。它直接改变 Token 预算、延迟、失败恢复和验证层的设计。
- **是否值得阅读全文**：是

### 3. GitHub Copilot Computer Use 与 Agent 工作区编排进入产品层

- **Source**：GitHub Copilot
- **Title**：GitHub Copilot can now interact with desktop apps with computer use；GitHub Copilot in VS Code, September 2026 releases
- **发布时间**：2026-10-01
- **Topics**：Computer Use、Desktop Automation、Agents Window、Workspace、Agent Merge、Scheduling
- **Priority**：P1
- **Original**：
  - https://github.blog/changelog/2026-10-01-github-copilot-can-now-interact-with-desktop-apps
  - https://github.blog/changelog/2026-10-01-github-copilot-in-vs-code-september-2026-releases/
- **What changed**：Copilot CLI 和 Copilot app 在 macOS / Windows 提供桌面 Computer Use 公开预览；VS Code 侧同步增加 Agent session 管理、工作区 / Dev Container 协作、任务调度、Agent Merge，以及从 Agent session 创建 Pull Request。
- **Technical details**：
  - Computer Use 可以读取可访问性内容和视觉上下文，点击、输入、滚动、拖拽并跨桌面应用执行流程；
  - 默认在控制桌面应用前请求批准，并支持组织级禁用；
  - Agents window 可以调度日常或每周任务；
  - Agent Merge 可以处理 review feedback、失败检查、冲突和 workflow rerun；
  - Agent session 可以直接进入 Pull Request 创建流程。
- **Why it matters**：Coding Agent 的执行边界从代码仓库扩展到桌面应用和 GUI-only 系统，任务生命周期也从“生成补丁”延伸到调度、审查、合并和重新运行。
- **是否值得阅读全文**：是

### 4. OpenAI GPT-6 构建指南：模型能力与 Agent Harness 成本边界协同设计

- **Source**：OpenAI
- **Title**：A practical guide to building with GPT-6
- **发布时间**：2026-10-02
- **Topics**：Agentic Coding、Computer Use、Prompt Caching、Inference Efficiency、Model Routing
- **Priority**：P2
- **Original**：https://openai.com/index/a-practical-guide-to-building-with-gpt-6/
- **What changed**：OpenAI 在官方首页将《A practical guide to building with GPT-6》列为 2026-10-02 的最新产品材料，继续围绕 GPT-6 系列的 Agent 构建方式展开。
- **Technical details**：与 9 月 29 日 GPT-6 Sol / Luna 发布所明确的方向一致：更低的调用成本、更强的 agentic coding 和 computer use、长对话缓存复用、可调 reasoning effort、工具开关不破坏缓存前缀。
- **Why it matters**：模型能力提升只有在 Harness 能保留缓存、控制推理预算和按任务阶段路由模型时，才会转化为整体任务成本下降。该材料适合作为模型与运行时协同设计的补充阅读。
