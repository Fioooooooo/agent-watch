# Agent 一手情报｜2026-10-07

## 每日摘要

本次扫描归档 **8 条高价值材料**，覆盖状态为 **`coverage incomplete`**。Cognition / Devin 与 Windsurf 两组强制来源本次没有取得可验证的官方最新入口证据，因此不能把它们解释为“无更新”。

### 1. Coding Agent 正在把“人在电脑前操作”纳入标准执行面

Cursor 在 10 月 6 日把 **Remote Control for local agents** 推入产品：Agent 仍运行在用户自己的电脑上，手机端只负责查看状态、继续对话和发送消息。它与 Cursor 9 月已经形成的长期目标、事件订阅、独立 VM 子 Agent、云端持续执行能力连在一起，进一步把 Coding Agent 从“远程云 Agent”扩展成“本地 Agent 的持续控制面”。

GitHub Copilot 在 10 月 1 日也把 Computer Use 放进 CLI / App，允许 Agent 操作没有 API、CLI 或 MCP 的桌面应用。两者共同指向一个执行边界变化：**Agent 的工具面正在从代码与服务 API 扩展到完整工作环境，同时需要新的权限、会话持续性和人工接管机制。** Cursor 的 Remote Control 值得读原文；Copilot Computer Use 作为持续观察项。

### 2. Harness 的核心能力正在向“可恢复的长任务运行时”集中

Claude Code 2.1.292、Gemini CLI 0.63/0.64、LangGraph 1.2.13/1.2.14、Qwen Code 0.25.1-preview 都在最近几个版本里直接触及 Agent runtime 的状态边界：子 Agent effort、workflow agent、prompt cache、sandbox 隔离、长循环 tool-output 限制、checkpoint 分支恢复、远程 workspace、SSE/daemon 会话，以及 ACP/A2A 的状态迁移。

这些更新不是同一个厂商的单点功能，而是在解决同一类工程问题：**当 Agent 从几轮工具调用变成持续运行的任务后，Harness 必须负责状态、恢复、上下文成本和权限边界，而不是只负责把下一次 prompt 发给模型。** Claude Code 2.1.292 与 LangGraph checkpoint 修复最值得阅读全文，Gemini CLI 和 Qwen Code 适合持续观察。

### 3. Agent 间协议正在进入更明确的状态机阶段

ACP 官方仓库近期继续推进 v2 相关 RFD，10 月 3～5 日出现 session steering、session resume 状态、background subagent 生命周期等提案；同时官方仓库最近仍在持续更新。结合 Gemini CLI 的 A2A V1→V2 设置迁移，可以看到协议层正在从“让 IDE 调 Agent”向**表达会话状态、取消、恢复、后台子 Agent 和长期连接**演进。

ACP v2 当前仍处于演进阶段，不应当按稳定规范使用；值得关注其 session lifecycle 与 durable/resumable transport 方向。

### 1. Cursor：Remote control for local agents

- **Source**：Cursor
- **Title**：Remote control for local agents
- **发布时间**：2026-10-06
- **Topics**：Coding Agent、Long-running Agent、Remote Control、Session Management
- **Priority**：P1
- **Original**：https://cursor.com/changelog
- **What changed**：Cursor iOS App 现在可以查看和回复运行在用户本机上的 local agents。
- **Technical details**：
  - Agent 不迁移到云端，仍运行在用户自己的电脑上；
  - 手机端连接到用户账户下已配对的电脑；
  - 可以查看 Agent 当前状态并继续发送消息；
  - 企业组织默认关闭 Remote Control，管理员可以在组织安全设置中开启；
  - 本机必须保持在线，Cursor 还提供保持电脑唤醒的设置。
- **Why it matters**：这把 Coding Agent 的“控制面”和“执行面”进一步分离。执行仍可以留在本地网络、文件系统和开发环境中，而移动端承担观察、干预和恢复任务的角色。对于长时间运行的本地 Agent，这是比单纯增加一个聊天客户端更有意义的运行时变化。

- **Why it matters**：Claude Code 正把“模型能力参数”“子 Agent 生命周期”“缓存边界”和“sandbox 权限”暴露为同一 Harness 层的可控状态。尤其是 workflow agent hook 和 sandbox 动态权限修复，对插件化 Agent runtime 的设计有直接参考价值。

### 4. LangGraph 1.2.13 / 1.2.14：checkpoint 分支恢复继续成为核心运行时语义

- **Source**：LangChain / LangGraph
- **Title**：langgraph 1.2.13 / 1.2.14
- **发布时间**：2026-10-05 ～ 2026-10-06
- **Topics**：Checkpoint、Recovery、Branching、Durable Execution
- **Priority**：P1
- **Original**：
  - https://github.com/langchain-ai/langgraph/releases/tag/1.2.13
  - https://github.com/langchain-ai/langgraph/releases/tag/1.2.14
- **What changed**：1.2.13 集中修复 checkpoint replay、branch fork、DeltaChannel 状态以及旧 checkpoint 更新路径；1.2.14 随后发布。
- **Technical details**：
  - replay update checkpoint 前先 fork；
  - older checkpoint 的 update_state 不再污染其他 branch；
  - abandoned branch 不再被 replay 到 DeltaChannel fork；
  - 子图 DeltaChannel 使用调用方解析出的 saver；
  - answered interrupts 不再继续出现在 get_state。
- **Why it matters**：这些修复体现了 durable Agent execution 与普通对话状态管理的差异。checkpoint 不只是“保存一份历史”，而是执行分支、恢复、重放和中断语义的一部分。对需要长任务、人工介入和失败恢复的 Harness，LangGraph 的这类实现值得持续跟踪。
- **是否值得阅读全文**：是

- **Source**：Agent Client Protocol
- **Title**：ACP v2 相关 RFD：session steering、background subagent survival、session resume state、durable/resumable HTTP/WS transport
- **发布时间**：2026-10-03 ～ 2026-10-05（提案 / 讨论）
- **Topics**：ACP、Session Lifecycle、Sub-agent、Recovery、Durable Transport
- **Priority**：P2

  - https://github.com/agentclientprotocol/agent-client-protocol
  - https://github.com/agentclientprotocol/agent-client-protocol/pulls
  - https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/announcements/acp-v2-draft.mdx
- **What changed**：ACP v2 draft 已在此前公开，近期继续出现 session steering、resume 后状态更新、后台 sub-agent 是否随 cancel 存活等 RFD。

- **Why it matters**：这些问题说明 ACP 的难点已经从消息互通进入 Agent lifecycle semantics。对于多 Agent IDE、远程 Agent 和长任务控制，这是比增加一个新 tool method 更基础的协议设计。
