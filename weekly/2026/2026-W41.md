# Agent / Harness 技术周报｜2026 W41

> **证据窗口：2026-10-03—10-09（北京时间，周五中午截止）。** ISO 周编号按出刊日期归属计算。已读取 [sources.md](../../sources.md) 和 10 月 3—9 日七份日报，原始材料合计 **32 条收录**，其中有跨日报重复、前期发布和补录，不能解释为“本周 32 项独立新发布”。
>

## 本周核心变化

**事实更新：** GitHub Copilot 的跨平台本地沙箱正式 GA；Codex 和 Claude Code 强化后台授权继承、工作区工具、Hook 异常安全与沙箱。Gemini CLI、LangGraph、Vercel AI SDK 同期继续解决状态持久化、checkpoint 分支和工具事件恢复。Google 则公开 AQuA，把生产会话轨迹、故障复核、源码定位和回归验证接起来。

**趋势分析：** Agent Harness 开始承担独立于模型推理的五项运行时责任：操作系统执行隔离、长期会话状态、可恢复的工具事件、跨任务调度和可追溯的生产质量治理。此次证据说明的是多个厂商在解决相似工程约束，不等于它们已经采用统一架构或协议。

## 一、Runtime / Sandbox：从授权弹窗走向执行强制边界

### 事实更新

2026 年 10 月 7 日，GitHub 宣布 Copilot 本地沙箱正式 GA，适用于 Copilot CLI、App 和 VS Code Agent Host。MXC 将统一策略映射为 Windows、macOS、Linux 原生限制，覆盖文件、网络、凭证以及受支持的 MCP 和语言服务器；企业可强制执行策略。官方强调沙箱限制工具执行，与所选模型分离。原文：[Copilot 本地沙箱 GA](https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/)。

Codex 0.161.0 明确后台任务继承发起轮次授权、修复线程历史和 SQLite 损坏恢复；10 月 8 日的 0.162.0 增加托管 Git worktree，强化 Linux/Windows 沙箱、MCP 状态及重试策略。原文：[Codex 0.161.0](https://github.com/openai/codex/releases/tag/rust-v0.161.0)、[Codex 0.162.0](https://github.com/openai/codex/releases/tag/rust-v0.162.0)。

Claude Code 2.1.295 增加命令和 HTTP Hook 的可配置失败关闭策略：`onFailure: "block"` 使启动失败、超时或异常退出的 Hook 能够阻断操作；并不意味着默认全部 Hook 都失败关闭。同期还改进插件重载、权限检查、后台会话和 MCP 重连。Copilot CLI 1.0.94 将实际 Shell 代码交给辅助权限裁决器，并允许企业禁用辅助授权、要求人工审批。原文：[Claude Code 2.1.295](https://github.com/anthropics/claude-code/releases/tag/v2.1.295)、[Copilot CLI 1.0.94](https://github.com/github/copilot-cli/releases/tag/v1.0.94)。

### 趋势分析

长期 Agent 的授权语义不再只是 `tool → allow/ask/deny`，还涉及动作来源、子任务继承、工作区与沙箱、扩展 Hook 失败、MCP 重连和环境恢复。下一步要验证的是跨阶段是否存在权限放大和异常状态绕过，尤其是工具先授权、后切换工作区或恢复后台任务的场景。

## 二、Context Engineering / Recovery：Session 已是执行状态而非对话文本

### 事实更新

Gemini CLI 10 月 2 日 nightly 加入追加式差量会话记录、有界历史窗口、原子状态持久化和损坏备份恢复；10 月 7—8 日又修复恢复时的工具消息、历史状态和会话轮次结构。10 月 2 日属于日报捕获的前序背景，不算 10 月 5 日之后的新发布。原文：[10 月 2 日 nightly](https://github.com/google-gemini/gemini-cli/releases/tag/v0.64.0-nightly.20261002.gc9096a847)、[10 月 7 日 nightly](https://github.com/google-gemini/gemini-cli/releases/tag/v0.65.0-nightly.20261007.gef59c532f)。

LangGraph 1.2.13 对 checkpoint replay、branch fork、DeltaChannel 和旧检查点更新路径修复：旧分支的更新不应污染其他分支，已回答中断不应继续残留。1.2.14 随后发布。Vercel AI SDK 7.0.134 修复流式恢复时**由模型提供商执行的工具事件**遗漏，并确保工具更新触发的异步错误传播。Qwen Code 0.25.1-preview 修复远程 Host 替换时的绑定关系、托管 Agent SSE 和 Hosted Harness 附着竞态。原文：[LangGraph 1.2.13](https://github.com/langchain-ai/langgraph/releases/tag/1.2.13)、[AI SDK 7.0.134](https://github.com/vercel/ai/releases/tag/ai@7.0.134)、[Qwen Code 0.25.1-preview](https://github.com/QwenLM/qwen-code/releases/tag/v0.25.1-preview.0)。

### 趋势分析

会话恢复需要重建的对象包含消息、工具执行事件、检查点分支、中断、权限以及工作区绑定。仅重建可见聊天记录无法保证工作不会重复执行，也不能保证恢复后的 Agent 正处于原来的分支与安全状态。Context Engineering、检查点和流式工具事件正在趋向同一个状态一致性问题。

## 三、Multi-Agent / Coding Agent：控制面与执行位置分离

### 事实更新

Cursor 10 月 6 日发布本地 Agent Remote Control，允许 iOS 查看、回复和继续本机 Agent；Agent 仍在原电脑上执行，机器必须保持在线，企业可控制开关。原文：[Cursor Changelog](https://cursor.com/changelog)。

作为窗口前背景，GitHub Copilot 10 月 1 日发布 Dynamic Workflows，支持通过代码定义串并行 Agent、结构化结果交换和人工检查点；9 月 30 日发布 HydraFusion 的单模型、级联和跨模型审查。它们不是本周 10 月 5 日后新发布，但与本周更明确的工作区、恢复和执行边界形成关联。原文：[Dynamic Workflows](https://github.blog/changelog/2026-10-01-dynamic-workflows-in-copilot-cli-and-the-copilot-app/)、[HydraFusion](https://github.blog/changelog/2026-09-30-hydrafusion-in-vs-code-and-the-github-copilot-app/)。

### 趋势分析

客户端负责观测和人工介入，工作流层负责阶段调度与检查点，运行时负责实际执行、工作区与授权。Cursor 的远程控制并不意味着 Session 已迁移到云端，Copilot 的多 Agent 工作流也不表示所有子 Agent 共享上下文。两者共同说明需要显式分离前端、运行位置与任务状态。

## 四、Protocol：ACP 会话生命周期仍处于提案推进阶段

### 事实更新

ACP v2 在 2026 年 7 月 20 日公开的是**草案**，不是本周发布的稳定协议。其核心变化之一允许 `session/update` 独立于用户 Prompt 轮次，支持持续的后台事件和消息标识。10 月 3—5 日日报继续跟踪到 steering、resume、后台子 Agent 生命周期和持久连接的 RFD 讨论。原文：[ACP v2 草案说明](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/announcements/acp-v2-draft.mdx)、[ACP 官方提案](https://github.com/agentclientprotocol/agent-client-protocol/pulls)。

### 趋势分析

Agent 可以在一个交互轮次结束后继续工作，使取消、暂停、恢复、推送更新及后台子 Agent 的生存期成为协议核心语义。需要跟踪具体提案是否合并、SDK 是否支持以及客户端是否能恢复状态。本周没有足够证据表明 MCP 或 A2A 出现同等级别的新稳定规范变更，不填充独立协议新闻。

## 五、评测与生产质量：Google AQuA 建立可复核故障证据链

### 事实更新

Google 10 月 8 日发布 AQuA 参考实现，在生产请求路径外读取最多 1,000 个会话的轨迹，检查行为与目标差异，对问题聚类、独立复核、跨扫描追踪，再关联部署时不可变源码快照的文件与行号。它不自行修改生产 Agent。其旅行规划案例有 32 个会话、1,583 个跨度，42 个初始发现聚合为 9 组，经复核保留 6 组；修复两个提示词缺陷后，完整会话通过数从 5/32 上升到 13/32。这是特定参考实验，不代表普遍收益。原文：[Google AQuA 工程文章](https://developers.googleblog.com/the-outer-loop-insights-first-an-ambient-quality-agent-that-diagnoses-your-production-agent/)。

OpenHands 1.26.0 也增加 `verify-openhands` Skill、`control-openhands` CLI 和可重复执行的功能验证配方。原文：[OpenHands 1.26.0](https://github.com/OpenHands/OpenHands/releases/tag/v1.26.0)。

### 趋势分析

Agent 质量治理正在从最终得分转向“轨迹—失败行为—子 Agent / 工具配置—源码版本—回归测试”的闭环。AQuA 还明确了抽样偏差、超长轨迹压缩、评审器误报和外部系统状态不能精确重放等开放问题。**本周最值得阅读全文的是 Google AQuA**。

## 六、新模型与 Harness 内部路由

### 事实更新

Anthropic 10 月 7 日发布 Claude Haiku 5.5，面向摘要、压缩、分类、数据库查询及 Coding 子 Agent 等高频任务，同时降低 Sonnet 5.5 缓存读取成本；Copilot 同期接入。原文：[Haiku 5.5 官方发布](https://www.anthropic.com/claude-haiku-5-5)。

OpenAI 10 月 8 日在 Responses API 新增 GPT-6.1 Sol 的 `service_tier: "ultrafast"`，减少输出 Token 之间的时间间隔；官方未承诺完整 Agent 任务统一提速幅度。原文：[OpenAI Release Notes](https://openai.com/products/release-notes/)。

### 趋势分析

Agent Harness 的资源选择开始包含主任务模型、局部子 Agent 模型、缓存复用、服务层级及总调用成本。应该比较完整任务成功率、延迟、工具调用数量、Token 和重试次数，而不是只看单次模型速度。Qwen、DeepSeek、Kimi、GLM 本周没有足够的新增官方证据形成独立主线，不得把来源缺失解释为无发布。
