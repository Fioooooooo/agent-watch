# Agent / Harness 技术周报｜2026 W39

## 本周结论

本周真正形成的主线不是单一产品功能，而是 Agent Harness 的状态边界与治理边界同时外移：

1. 状态边界从 conversation 扩展到 Project、Session、PR / Review 等长期软件工程对象。
2. 执行边界从“能调用工具”扩展到工具验证、权限审批、运行时观测和组织级治理。
3. 扩展边界从“安装一个插件”扩展到可验证的软件供应链、版本证明和隔离执行。
4. 模型竞争开始直接影响 Harness 的预算、缓存、重试和任务拆分策略。

本周没有足够证据形成独立的 Protocol（MCP / ACP / A2A）或 LangChain / Vercel AI SDK / OpenHands 主线，因此不单独扩展相关章节。

## 1. Harness：状态单位从对话转向工程对象

### 事实更新

Anthropic 在 2026 年 9 月 17 日发布 Claude Code Projects 重设计。Project 由资料容器变为长期协调层，coordinator 负责拆解、派发、跟踪、审查和汇总；每个 thread 是独立的 Claude Code cloud session，拥有自己的 branch 和 repo copy，还可以继续使用 subagents、loops 和 workflows。多个 thread 通过 Project-level shared memory 共享决策、约束和历史结果。官方原文：<https://claude.com/blog/projects-redesigned>

GitHub Copilot 在 2026 年 9 月 18 日把 code review 推向持续运行的 Review Agent：Agent 可以调用 shell 工具验证修改，Lite review 会综合多个 Agent 的 findings，findings 会跨后续 commit 和重复 review 保留状态，并区分 Open、Resolved since last review 与 Previously missed。官方原文：<https://github.blog/changelog/2026-09-18-copilot-code-review-an-improved-review-experience/>

OpenAI Codex 在 2026 年 9 月 22 日发布 rust-v0.156.0，公开 Release 资产包含多平台构建产物、bwrap 相关资产和 Sigstore 签名文件。现有 Release 正文不足以确认新的 Agent loop 或权限语义，但可以确认 sandbox 运行时组件与二进制验证链路被纳入同一交付面。官方原文：<https://github.com/openai/codex/releases/tag/rust-v0.156.0>

### 趋势分析

本周不同产品指向同一个结构变化：

- Project 是长期目标、共享 memory 和协作规则的状态边界；
- Session / Thread 是可独立恢复和观察的执行边界；
- PR / Review 是面向交付生命周期的持续状态边界；
- Branch、repo copy、workspace 和 sandbox 是代码变更的物理执行边界。

这比“给单个对话增加更多上下文”更接近生产级 Harness 的真实形态。未来 Harness 需要管理多个生命周期对象，并在每次模型调用前重新装配 Project state、Session runtime state、workspace state 和 review state。

## 2. Context Engineering：上下文被拆成可治理的数据层

### 事实更新

本周 Claude Projects 将 shared memory 放在 thread/session 之上；Qwen Code 相关日记录得 context usage、compression ownership、Computer Use observation 大小、shell output budget 和模型往返次数；GitHub Copilot 的持续 review 则把 findings 作为 PR 生命周期状态保存，而不是每次重新从零生成。

### 趋势分析

Context Engineering 的重点正在从“怎样把更多内容塞给模型”转向“哪些状态在什么作用域持久化，哪些状态只在当前执行阶段可见”。值得持续观察的层次包括：

- Project memory：长期决策、约束、协作习惯；
- Session context：当前任务、工具调用、压缩与恢复状态；
- Worker brief：子任务目标、输入边界和返回格式；
- Tool observation：shell、browser、MCP 的即时结果；
- Review state：PR、commit 和 findings 的持续判定；
- Provenance / policy state：输入来源、信任级别和授权依据。

本周尚未看到统一的跨厂商状态协议，但各家已经在产品层面分别实现这些层次。

## 3. Multi-Agent：从“子 Agent 调用”转向长期并行协作

### 事实更新

Claude Projects 的 coordinator、独立 thread、Project shared memory 和 thread 内部的 subagents / loops / workflows，形成明确的多层执行结构。GitHub Copilot Lite review 则以多个 review Agent 聚合结果，并把聚合后的 findings 绑定到后续 commit。

### 趋势分析

Multi-Agent 正在出现两种稳定形态：

1. **任务编排型**：coordinator 将复杂目标拆为多个独立 session，适合长期工程任务。
2. **生命周期协作型**：多个 Agent 围绕 PR / Review 这类外部工程对象持续工作，状态由对象本身承载。

这两种形态都降低了对“单一超长上下文”的依赖，但也提高了冲突解决、状态一致性、handoff 以及人工 steer 的设计要求。Claude Projects 明确继续使用正常 PR / merge conflict 处理代码冲突，说明多 Agent 并行并不自动消除软件工程中的合并成本。

## 4. Runtime / Sandbox / Recovery：安全执行面成为产品能力

### 事实更新

9 月 22 日公开披露的 Plugin4Shell 指出，主流 Coding Agent 插件链路可能仅保存目标 SHA，却未可靠验证最终工作树与目标 commit 一致；后台自动更新场景下，恶意代码可在无需用户额外点击时进入执行路径。披露涉及 Claude Code、Codex、GitHub Copilot 和 Gemini CLI 的插件机制。原文：<https://www.air.security/blog-posts/plugin4shell>

Codex rust-v0.156.0 的 Release 资产同时包含 sandbox 相关 bwrap 文件和 Sigstore 签名文件，表明运行时隔离与发布验证正在成为分发系统的一部分。官方原文：<https://github.com/openai/codex/releases/tag/rust-v0.156.0>

### 趋势分析

本周安全信号把扩展机制的设计要求进一步具体化：

- 来源可信不等于执行对象可信；
- SHA pinning 不等于工作树内容已被证明；
- 插件、Skills、MCP server、Hooks 都需要安装时重验证；
- 运行时权限、网络访问、凭证可见性和更新策略必须绑定到扩展证明；
- sandbox 需要从“隔离命令”升级为“隔离扩展生命周期”。

Recovery 方面，本周没有出现新的独立架构发布，但 Claude Projects、PR review state 和 Codex runtime packaging 都在推动一个共同方向：恢复对象不应只是 conversation transcript，而应包含 session、workspace、权限和扩展状态。

## 5. Tool Governance / Observability：企业化从能力开放转向可审计

### 事实更新

GitHub Copilot 在 9 月 22 日增加 Copilot app 的 OpenTelemetry 配置，并在 JetBrains 版本中加入 AI-assisted tool approvals、组织级 Skills / custom instructions、持久化 MCP 工具控制以及 plan mode。官方原文：

- <https://github.blog/changelog/2026-09-22-opentelemetry-in-the-github-copilot-app/>
- <https://github.blog/changelog/2026-09-22-new-features-and-improvements-in-copilot-for-jetbrains/>

### 趋势分析

企业级 Agent Harness 的核心能力正在收敛为三类：

1. **执行追踪**：session、模型请求和工具调用可导出到监控系统；
2. **风险分级审批**：低风险工具自动批准，高风险操作保留用户决策；
3. **组织级治理**：统一管理 Skills、instructions、MCP tools 和 plan mode。

这套能力直接决定 Agent 能否进入可审计、可回溯和可运营的开发流程。MCP 在本周没有新的协议语义，但 MCP 工具已经进入组织级治理对象。

## 6. Model：模型效率开始成为 Harness 设计变量

### 事实更新

OpenAI 在 9 月 23 日发布 GPT-6 Sol / Luna，强调 coding、computer use、缓存与推理效率以及更低 API 成本。官方原文：<https://openai.com/index/introducing-gpt-6-sol-and-luna/>

Anthropic 在 9 月 23 日发布 Claude Opus 5.5，强调 agentic coding、long-running task、错误恢复、更低价格、更低 cache read 成本和更快输出。官方原文：<https://www.anthropic.com/claude-opus-5-5>

### 趋势分析

模型发布的评价单位正在从“单次调用能力”转向“完整任务成本”：

- 任务完成需要多少次模型往返；
- 上下文缓存能否复用；
- 错误恢复需要多少重试；
- 子任务拆分后总 token 成本如何变化；
- Computer Use 的观察与动作循环是否可控。

因此，模型层的效率不再只是模型选型问题，也会直接改变 Harness 的路由、checkpoint 频率、worker 数量、上下文重放和重试策略。随着模型公司将缓存、调用次数和长任务效率公开为产品卖点，这一约束会继续强化。

本周 daily 中没有足够新的协议语义或规范变更，MCP 主要作为工具治理对象出现，ACP / A2A 未形成独立事实更新。

### LangChain / LangGraph、Vercel AI SDK、OpenHands

本周 daily 没有形成足够高价值、且经一手来源验证的架构级新材料，不为完整性填充。

## 8. 下周持续观察

1. Claude Projects 是否进一步开放 Project-level memory、worker session 和资源控制的更细粒度配置。
2. GitHub Copilot 是否为 code review findings 提供更完整的审计、策略和跨仓库治理能力。
3. Codex 是否发布 rust-v0.156.0 的完整变更说明，明确 bwrap、签名和 sandbox 资产对应的运行时语义。
4. Plugin4Shell 影响范围内的厂商是否补充 commit provenance、更新前重验证、隔离执行和管理员策略。
5. OpenAI 与 Anthropic 是否继续把 cache、调用次数、长任务恢复和完整任务成本纳入模型 API 的公开指标。
6. MCP 工具治理是否进一步演化为统一的组织级 tool registry、审批策略和 provenance 记录。
