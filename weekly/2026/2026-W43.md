## 本周摘要

**一、工具执行结果“未知”正在成为独立运行状态，而不是可直接重试的失败。** Qwen Code 0.26.0 将执行证据和已持久化的文件操作回执纳入恢复流程；Claude Code 2.1.307 限制断线后 HTTP MCP 工具的重试范围；Vercel AI SDK 7.0.149 引入未正常结束的流式响应状态。三者针对不同层级，但都在阻止“没有收到结果”被误判成“操作没有发生”。这是本期最有工程含量的共同信号，推荐阅读 [Qwen Code v0.26.0](https://github.com/QwenLM/qwen-code/releases/tag/v0.26.0) 和 [AI SDK 7.0.149](https://github.com/vercel/ai/releases/tag/ai%407.0.149)。

**二、安全边界必须覆盖执行器、沙箱、配置文件和审批消费端。** Claude Code 2.1.309 集中修复了 shell 初始化、符号链接、MCP 配置、后台命令与 Hook 相关的隔离或授权缺陷；AI SDK 则修复重复批准响应与 `toolChoice: 'none'` 下的工具执行路径。只在模型工具调用前设置 `allow/ask/deny`，不足以保证完整执行链安全。推荐阅读 [Claude Code v2.1.309](https://github.com/anthropics/claude-code/releases/tag/v2.1.309)。

**三、上下文预算与持久执行状态进一步分开管理。** Qwen Code 开始从工具结果产生到注入模型前计量内容大小，让被截断的预览仍可恢复完整结果，并修复压缩后上下文的恢复；Claude Code 修复超大嵌套 `CLAUDE.md` 导致反复压缩的问题。方向是将完整工具产物留在外部状态层，模型上下文只承载经过预算控制的视图。此项值得持续观察，但当前不意味着业界形成统一的上下文存储协议。

## 1. Runtime / Recovery：不能把“未知结果”当作失败重试

### 已证实事实

**Qwen Code v0.26.0（北京时间 10 月 22 日）**新增多项与持久运行直接相关的实现：

- Hosted Turn 恢复会向 Runtime Broker 请求执行证据；不能证明执行结果时，标记为 **unknown**，而不是暂时故障。未知状态的任务会暂停等待后续检查，避免反复执行取消操作或过早判定 FAILED。[版本说明](https://github.com/QwenLM/qwen-code/releases/tag/v0.26.0) · [执行证据 PR #14669](https://github.com/QwenLM/qwen-code/pull/14669) · [未知结果保留 PR #14681](https://github.com/QwenLM/qwen-code/pull/14681)。
- 对已经持久化文件操作回执的 private CSI 任务，新的 Hosted owner 可以接手完成；冷恢复使用保存的工具响应，避免重复文件写入或额外模型调用。[PR #14523](https://github.com/QwenLM/qwen-code/pull/14523) · [PR #14695](https://github.com/QwenLM/qwen-code/pull/14695)。
- Writer 租约失效后，Session journal 会重新协调已提交记录及未完成记录；已提交、尚未消费的输入可以重新唤醒会话。版本也增加 Workspace 隔离会话的预热以及同一存储上多会话并行运行的支持。[PR #14570](https://github.com/QwenLM/qwen-code/pull/14570) · [PR #14603](https://github.com/QwenLM/qwen-code/pull/14603) · [PR #15026](https://github.com/QwenLM/qwen-code/pull/15026)。

**Claude Code v2.1.307（北京时间 10 月 22 日）**修复 HTTP MCP 连接中断后可能重复发送工具调用的问题，改为仅对**只读或幂等工具**自动重试。[官方 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.307)。在 **v2.1.309（10 月 23 日）**，自托管 Runner 迁移到新 Runner 时，Agent 会获知被中断的工具调用并将执行结果标记为未知。[官方 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.309)。

**Vercel AI SDK 7.0.149（北京时间 10 月 23 日）**新增 `interrupted` 结束原因，用于表示提供商流未发出正常完成信号：保留部分输出，停止后续工具执行、Agent 自动继续和界面自动跟进。**边界：本次先提供公开类型与消费端处理，提供商侧的中断检测和事件发出尚待后续实现**；因此不能宣称所有提供商已经具备正确的中断识别。[官方 Release](https://github.com/vercel/ai/releases/tag/ai%407.0.149)。

### 趋势分析与工程取舍

这三个产品分别控制 Runtime Broker、工具调用重试和模型流事件，出现了同一类分布式系统问题：**请求发出后失去响应，无法仅凭网络异常确认副作用是否发生**。

对于带副作用的 Agent 工具，恢复协议至少要区分 `not_started`、`running`、`succeeded`、`failed` 与 `outcome_unknown`，并使用持久化操作 ID、回执、状态对账及明确的重试策略。不应把“可重试”理解为“必定只执行一次”；只有幂等操作或经服务端去重/核验的操作，才适合自动重放。引入未知状态会增加等待、对账和人工介入的成本，但相比重复支付、重复改文件或重复调用外部 API，这通常是必要取舍。

值得做的验证：在工具实际完成但响应丢失、Broker 崩溃、Runner 迁移、审批回执延迟四种故障下注入中断，检查副作用次数、最终状态及恢复后的证据链。

## 2. Sandbox / Permissions：策略需要在多个执行边界同时成立

### 已证实事实

**Claude Code 2.1.309**修复的安全问题横跨多个层次：macOS/Linux 的沙箱 Bash 命令曾在沙箱外运行 shell 启动文件；macOS 的 `denyWrite` glob 规则在符号链接路径下可能未作用于真实位置；沙箱命令或自动接受的编辑可能修改通过 `--mcp-config` 指定的配置；已禁用的 MCP server 可能因后续授权对话重新连接。版本同时修复 Windows PowerShell Hook 在特定环境下未能按错误退出码阻止操作，以及 Linux 后台命令超出会话生命周期后的写入禁止失效。[官方 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.309)。

**Claude Code 2.1.307**新增 `claude_code.safety_event` OpenTelemetry 事件，将权限规则、自动授权、安全检查、Hook 和沙箱对工具调用的阻止或要求批准显式记录。[官方 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.307)。

**Vercel AI SDK 7.0.149**只处理同一次工具调用的首个批准响应，防止重复或冲突的批准让工具执行两次，或同时执行和拒绝；并修复 `toolChoice: 'none'` 的执行约束，除向提供商传递禁用选择外，还在本地工具执行与流式工具片段消费前实施拒绝。[官方 Release](https://github.com/vercel/ai/releases/tag/ai%407.0.149)。

**Gemini CLI 10 月 22 日 nightly**收紧对不可信标志的检查范围，只对外部输出应用相应检查，并保存已经批准的标志；同版本增加通过 `exec stdio` 将 IDE 伴随服务桥接到容器沙箱的能力。这些属于 **nightly**，不能等同稳定版生产承诺。[官方 Release](https://github.com/google-gemini/gemini-cli/releases/tag/v0.67.0-nightly.20261022.g09d81bf11)。

### 趋势分析与工程取舍

**模型提出动作、Harness 审批、命令实际执行、子进程与插件运行、审计事件**是不同的边界。任何一层错误继承权限或绕过真实路径校验，都可能让上游批准失效。

与其扩大工具白名单，工程上更应设计统一的授权主体与对象标识，按规范化后的文件路径、真实执行上下文及当前策略做最终执行前校验；对后台进程、Hook、MCP server、工作区迁移做生命周期约束。安全事件需要标明规则来源与执行阶段，便于重建“为何允许或拒绝”。代价是更复杂的跨平台差异和更高的权限误判排查成本。

本周这些修复证明原有边界存在可触发的缺陷，不等于已确认实际遭利用，也不意味着全部攻击面已经消失。

## 3. Context Engineering：上下文是视图，工具产物与恢复证据要独立保存

### 已证实事实

**Qwen Code 0.26.0**增加工具结果从产生端到注入模型端的大小计量，支持预览预算并让截断预览可恢复；同时修复 `web_fetch` 被重复截断的问题，保留原始内容的可恢复路径，并修复恢复过程中压缩上下文丢失的情况。[官方 Release](https://github.com/QwenLM/qwen-code/releases/tag/v0.26.0) · [结果预算 PR #14545](https://github.com/QwenLM/qwen-code/pull/14545) · [预览恢复 PR #14546](https://github.com/QwenLM/qwen-code/pull/14546) · [压缩恢复 PR #14702](https://github.com/QwenLM/qwen-code/pull/14702)。

**Claude Code 2.1.309**修复加载巨大嵌套 `CLAUDE.md` 后持续重复压缩的问题，对超出大小限制的嵌套文件只加载开头部分。[官方 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.309)。**Claude Code 2.1.307**还修复模型读取大量 PDF、图片或工具结果时压缩反复触发的情况，以及重启后压缩窗口设置未正确保留的问题。[官方 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.307)。

### 趋势分析与工程取舍

长时间运行的 Agent 应分离三种内容：**原始完整产物**（可审计和回查）、**任务持久状态**（决定能否恢复）、**当前模型视图**（受 Token 预算约束）。如果仅在消息历史中保存截断文本，模型后续无法追查细节；如果把完整产物反复注入，又会提高缓存失效和压缩振荡的风险。

合理设计是让工具产物拥有稳定引用、大小与截断标记，按需检索片段，并让压缩摘要引用原始证据，而非代替原始证据。需要特别评测“摘要压缩后再恢复”是否改变工具已执行状态与后续授权。当前只确认实现方向，未发现本周发布的跨厂商统一格式。

## 4. Multi-Agent、Coding Agent 与协议：角色、会话和工作区仍需明确边界

### 已证实事实

Qwen Code 0.26.0 支持按 Session 刷新 Skills/Extensions、持久 Workspace 产物库，以及同一共享 Workspace 存储上的并发会话；这些能力与 Hosted 恢复机制出现在同一版本。[官方 Release](https://github.com/QwenLM/qwen-code/releases/tag/v0.26.0)。

Claude Code 2.1.309 修复分栏 Agent 队友未继承负责人的 `--tools` 和禁止规则的问题；同一版本的 `/claude-api` 技能将 Managed Agents 子团队示例切到 `multiagent_20261001`，默认启用动态工作流。此处是**技能模板/配置变化**，不是全行业协议升级。[官方 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.309)。

Gemini CLI 10 月 23 日 nightly 修复非交互模式在取消之后仍可能执行工具的行为，并对 A2A server 的 Token 使用元数据进行保持和对齐。[官方 nightly](https://github.com/google-gemini/gemini-cli/releases/tag/v0.67.0-nightly.20261023.ga713410ab)。

### 趋势分析与工程取舍

多 Agent 的协作对象不仅是“子 Agent 返回的一段文字”，还包括 Session 归属、工作区共享、子进程权限、操作回执与跨恢复的执行证据。**并发共享工作区不等于具备冲突隔离**；文件冲突、写入所有权、策略继承仍需独立测试。

本期没有在定向核验中发现足以组成独立主线的 **MCP / ACP / A2A 稳定规范更新**。Gemini 的 A2A 修复和 Qwen/Claude 的 MCP 生命周期修复属于实现层变化，不应写成协议已升级。未执行所有协议来源的全量检查，故不能断言“本周协议没有更新”。
